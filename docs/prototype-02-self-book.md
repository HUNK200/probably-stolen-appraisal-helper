# 原型验证 02：自制手册能否稳定停在左侧

> 目的：确认 R03「把手册固定到屏幕左侧」到底是**改个坐标就行**，还是**得自己托管面板**。
> 这是整个项目最后一个未知数——验证完，实现路径就定了。
> 前提：`mods/appraisal_helper` 已启用（验证 01 已通过）。

---

## 为什么先做这个

验证 01 已经确认：原版手册会**挡住**右侧鉴别界面，必须拖开才能操作。这意味着：

- 需求成立：自动把手册摆到左边确实有价值。
- 但原版「每次出现位置不固定」，所以我们**必须自己指定位置**，不能依赖原版。

关键问题是：这个位置好不好控制？三种可能，对应三条完全不同的实现路线。

| 观察到的情况 | 说明 | 后续路线 |
| --- | --- | --- |
| `posX/posY` 能精确控制，且能贴近屏幕左边缘 | 最理想 | JSON 配置即可，几乎零代码 |
| 能控制但会受窗口分辨率影响 | 可接受 | 代码里按 `Screen.width` 动态算 |
| 面板位置被原版逻辑覆盖，改了也不生效 | 最麻烦 | 需要在打开后强行 `SetPosition`，甚至自己托管面板 |

## 操作步骤

> 纸质手册**只存在于商店场景**，所以必须先载入一个存档。

### 1. 打开纸质手册编辑器

1. 载入一个存档，进入店里。
2. 按 `F9` → 左列 `Special` → `Modding Panel` → `Paper Editor`。

### 2. 新建一本测试手册

在 **Book** 标签页的 *New book* 下：

| 字段 | 填什么 |
| --- | --- |
| 模组 | 选 `Appraisal Helper` |
| ID | `test_guide` |
| 起点模板 | 选**「鉴定指南」**那一项（便于直接对比原版） |

点 **Create and edit**。它会写入并打开：

```
<游戏目录>\Mods\appraisal_helper\Books\test_guide.json
```

### 3. 把它拖到屏幕最左边缘

- 直接拖动面板本身，尽量贴住左边，但**不要超出屏幕**。
- 松手后等 1 秒（编辑器会自动保存）。

### 4. 记录四个值

在右侧 **Inspector** 里找这本书的位置字段（可能叫 `posX` / `posY`，也可能是 X / Y）：

```
posX =
posY =
```

如果找不到字段，跳过，我从 JSON 文件里读。

另外记录（能答多少答多少）：

```
屏幕分辨率（游戏设置里看）：
面板宽度大概占屏幕几分之几：
拖动之后有没有自动弹回原位：
```

### 5. 多翻几页确认外框还在

确认翻页按钮、页码、关闭按钮都正常——这些是原版外框提供的，我们后面要沿用。

### 6. 退出编辑器，汇报

**不需要**重新部署、不需要改代码。做完把上面几个值贴给我即可。

## 我会做什么

拿到 `posX` 之后：

1. 我读一遍 `Mods/appraisal_helper/Books/test_guide.json`（只读）；
2. 把实际字段结构记进 `docs/mod-api-notes.md`，替换掉「待确认」；
3. 把 `posX` 的取值方案（固定值 vs 按分辨率计算）定下来，写进需求的 R03；
4. 然后开始写第一段真正的功能代码：**在合适时机 `OpenPaper` 并设置位置**。

## 记录（2026-11-12 实测，100-REV13）

```
posX = -564
posY = 11.25
屏幕分辨率 = 未记录
拖动后是否弹回：否
外框（翻页/页码/关闭）是否正常：正常

其它现象：
- 手册可以成功创建，位置可以拖到左侧。
- Paper Editor 的控制面板目前是英文界面。
```

### 结论 1：手册能创建、能拖到左侧 ✅

`(-564, 11.25)` 这个位置可用，说明「固定在左侧」在视觉上没问题，R03 成立。

### 结论 2：⚠️ 编辑器不会把位置写进 JSON

实测读 `Mods/appraisal_helper/Books/test_guide.json`，顶层字段只有：

```
id, title, background, width, height, chrome, templates, pages, locales
```

**没有 `posX` / `posY`。** 而从 Inspector 里能读到 `-564, 11.25`，说明：

- 坐标是**运行时值**，编辑器没有序列化它；
- 或者是「新建时用模板默认值，用户拖动后没有触发保存该字段」。

社区指南里明确写了 `posX`/`posY` 是合法字段（原版指南用 `-450, 0`），所以下一步不是猜，而是**手工把这两个字段加进 JSON，看游戏认不认**。

### 下一次验证（下次开工第一件事）

1. 在 `mod/Books/test_guide.json`（仓库里已有编辑器产出的副本）里手工加上：

```json
"posX": -564,
"posY": 11.25,
```

2. `scripts\build.bat && scripts\deploy.bat`（部署已改为同步整个 `mod/` 目录，`Books/` 会一起过去）
3. 进游戏打开这本书，观察：
   - 打开位置是不是固定在左侧？
   - 换个分辨率/窗口尺寸，位置会不会跑偏？

三种结果对应三条路线：

| 结果 | 路线 |
| --- | --- |
| 认 `posX` 且换分辨率不跑偏 | JSON 写死即可，R03 零代码 |
| 认 `posX` 但跟着屏幕尺寸漂移 | 代码里按 `Screen.width` 算，再用 `SetPosition` |
| 不认 `posX` | `OpenPaper` 之后强制 `SetPosition`，仍不可控才考虑自己托管面板 |
